## 一、项目介绍

### 它解决的问题

"套餐加钱换饮料"这件事，菜单上每个选项都标着 `+ ¥1.5`、`+ ¥8`、`+ ¥13`，但真正掏钱时你面对的是三个不同的问题：

1. **菜单补差 ≠ 实付差额。** 券、门槛、套餐自身优惠都会改变最终价格。
2. **看着更便宜，可能实际更贵。** 换掉一张券绑定的商品，券会失效——菜单元件降 5 毛，实付可能多 8 块 6。
3. **预算约束下的"最值"没有排序依据。** 同样 5 块钱，能换的东西差很多。

### 它做的三件事

| 输出 | 数据来源 |
|---|---|
| 改了什么 | `query-meal-detail` 的 `rounds[].choices[]`，加价取自 `diffPrice` |
| 真实多花多少 | 对原餐与候选**各调用一次** `calculate-price`，取两者 `price` 之差 |
| 得到什么 | 替换项名称 + 是否触发券失效 + 每元收益说明 |

### 与同类作品的区别

同类作品多停在"列出候选 + 给出整单差价"。本项目的差异在**归因**：

```
ΔP = ΔM_menu − ΔA + ΔG + ε
```

把差价拆成 **菜单补差 / 券影响 / 其它费用 / 未归因残差** 四项，并强制残差显式披露（≤2 分不显示，3–500 分标注，>500 分该候选只出总价）。同时用矩阵表把 `菜单补差 †` 与 `实付多花 ✓` 分成两列——**同一个数字不允许同时充当两种口径**。

### 一个只有真问过服务端才会知道的结论

门店券**不能**与套餐内替换叠加。把套餐里的可乐换成「麦咖啡™冰美式中杯」（替换项 code 恰好是 `507411`，与门店 9.9 元券绑定商品一致），带上券请求计价，服务端直接拒绝：

```json
{"success":false,"code":600012,"message":"促销规则不支持该商品"}
```

同一张券用在**单点**商品上则正常生效：原价 ¥19.00 → 实付 ¥9.90，抵 ¥9.10。

所以本项目不会假设"有券就更便宜"，只会报告服务端实际接受的结果。这也是为什么归因表里"券的影响"经常是 ¥0.00，而且我们会把拒绝原因原样打出来。

## 二、安装方法

### 环境要求

- Node.js ≥ 18（只用内置 `fetch`，**零依赖**，不需要 `npm install`）
- 一个麦当劳 MCP Token：到 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) 手机号登录后激活

### 1. 获取代码

```bash
git clone https://github.com/<your-name>/maimai-plus-one.git
cd maimai-plus-one
```

### 2. 配置令牌

```bash
export MCD_MCP_TOKEN=你的令牌        # macOS / Linux
$env:MCD_MCP_TOKEN="你的令牌"        # Windows PowerShell
```

令牌只从环境变量读取，代码不会写入任何文件、日志或快照。仓库内的 `mcp-config.example.json` 仅含占位符。

### 3. 自检

```bash
node scripts/cli.mjs stores --city 上海 --keyword 华旭
node scripts/cli.mjs detail --store 1450713 --meal 9900005466
```

### 4. 在 WorkBuddy 中使用

把 `skill/SKILL.md` 放入 `~/.workbuddy/skills/maimai-plus-one/`，重启会话后直接说：

> 我点了巨无霸三件套，最多再加 5 块，想把饮料换成咖啡，有什么真实可选？

Skill 会按 SKILL.md 的 S0–S7 流程调用工具，并在输出中附带门店与抓取时间。

## 六、运行测试

```bash
node --test tests/engine.test.mjs
```

13 项全部通过，核心是 4 个归因算例（残差必须为 0）：

| 算例 | ΔP | 菜单补差 | 券影响 | 残差 |
|---|---|---|---|---|
| 单轮换奶昔 | +800 | +800 | 0 | 0 ✓ |
| 两轮同时替换 | +1050 | +1050 | 0 | 0 ✓ |
| 换掉券绑定商品 | **+860** | −50 | +910 | 0 ✓ |
| 加价跨过券门槛 | +300 | +800 | −500 | 0 ✓ |

第三个算例是本项目的存在理由：只按 `diffPrice` 会得出"还便宜 5 毛"，实际多花 8.6 元。
