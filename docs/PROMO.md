## 二、长文版（掘金 / V2EX / 少数派）

**标题**：我给麦当劳套餐做了个"加一点"决策器——难点不在推荐，而在把差价算平

**开头**：

点套餐时最常遇到的一幕：可乐想换成咖啡，菜单上写着 `+ ¥1.5`，可你真正付的钱未必只多 1.5 元。券、门槛、套餐自身的优惠，每一个都会动最终价格。

所以我做了个小工具，只回答三个问题：换哪一样、真实多花多少、换来的到底是什么。

**正文骨架**：

1. **它到底在算什么**
   - 从套餐结构里取出每一轮的可替换项和公示差价（`diffPrice`）
   - 对"原餐"和"换之后"各调一次官方计价，拿到真实应付
   - 把两个数的差，拆成 `菜单补差 / 券影响 / 其它费用 / 未归因残差`
   - 公式：`ΔP = ΔM_menu − ΔA + ΔG + ε`，四项必须加得平

2. **为什么必须拆**
   举个会翻车的例子：某张券绑定的是套餐里的薯条。你把薯条换成玉米杯，菜单看着便宜 0.5 元——但券失效了，实际多花 8.6 元。
   只算 `diffPrice` 会得出"还便宜了 5 毛"，只有把 `−ΔA` 拉进来才对得上账。

3. **几个真实数字**（2026-10-25 实测，门店 1450713）
   - 巨无霸三件套 36.50 元，换大杯鲜萃咖啡 → 38.00 元（+1.50）
   - 同一份套餐换麦咖啡冰美式 → 45.50 元（+9.00，超预算就只列不推）
   - 3 个套餐 81 个替换项：18 项 ≤1 元，3 项不加反降

4. **踩到的坑**
   - 套餐内替换**不能用券**：`{"success":false,"code":600012,"message":"促销规则不支持该商品"}`；同样的券用在单点商品上正常（1900 → 990）
   - `roundList` 的 `round` 参数官方零文档，属实测确认，因此代码里保留了失效探测与降级开关
   - 基线必须显式指定默认组合，否则服务端会用它自己的隐式默认，带一笔看不见的补差

5. **刻意不做的**
   不跨套餐比较（补差是相对各自套餐的，绝对值不可比）；不做外送与团餐（到店拿不到满减规则）；不给营养与过敏原结论（没有数据就不下判断）；全链路只读，不下单。

6. **怎么看**
   演示页是真实抓取的**离线快照**，双击 HTML 就能开，不需要令牌——因为官方服务是账号态的，没有 mock，任何"在线 demo"要么带别人的账号，要么就是编的。

**结尾**：如果你也每天在"加几块钱换饮料"上犹豫，欢迎试用后告诉我哪里算得不对——我把归因残差单独列出来，就是为了让它可被质疑。
