# 麦麦加一点

给一份**已经选好的**套餐加一点预算，换掉其中一项（通常是饮料或小食），并且把这点钱花在了哪里说清楚。

## 0. 一句话能力与不做什么

**做**：在真实门店菜单里枚举套餐内可替换项 → 对原餐与候选分别调用官方计价 → 把差价拆成「菜单补差 / 券影响 / 其它费用」→ 在预算内排序 → 给出可复制到结算页的选项名。

**不做**：跨套餐比较、外送与团餐、营养与过敏原结论、下单。

## 1. 适用边界

| 项 | 取值 |
|---|---|
| 渠道 | 仅到店自取（`orderType=1`, `beType=1`，不传 `beCode`） |
| 规模 | 单人、单套餐、每次只换一轮 |
| 品牌 | 只比较麦当劳自家方案，**禁止**与其他任何品牌做对比 |
| 写操作 | 全链路只读，永不调用 `create-order` / `auto-bind-coupons` / `draw-lottery` |

## 2. 会话握手：四个必填要素

| 要素 | 缺省处理 |
|---|---|
| 门店（城市+关键词，或收藏店） | 缺则问；返回多家时必须让用户选，**禁止默认取第一家** |
| 原套餐 | 缺则列出该店套餐让用户选；同名多个 code 必须问 |
| 额外预算（整数元） | 缺则默认 5 元并明确告知 |
| 目标（想喝咖啡 / 想少糖 / 想更饱 / 想换小食） | 缺则问；识别不了就列出同轮全部选项让用户挑 |

## 3. 执行流程

| 步 | 动作 | 工具 | 失败/中断处理 |
|---|---|---|---|
| S0 | 锁门店 | `query-nearby-stores {beType:1, searchType:2, city, keyword}` | 多家→让用户选；`businessStatus` 非营业→提示换店 |
| S1 | 锁套餐 | `query-meals {storeCode, orderType:1, beType:1}` | 用户说"巨无霸"匹配多个 code→必须问 |
| S2 | 建结构表 | `query-meal-detail {storeCode,1,1,code}` | `rounds` 为空→告知"这个套餐没有可替换项" |
| S3 | 意图→候选池 | 本地规则（见第 4 节） | 命中 0 项→明说没有 + 给放宽选项 |
| S4 | 找券 | `query-store-coupons {storeCode,1,1}` | 券只覆盖单点商品→记录拒绝原因，不假设可用 |
| S5 | 双方案核价 | `calculate-price` 带显式 `roundList` | `success:false`→记录 code/message，不得当成"无价格" |
| S6 | 归因 | 本地（见第 5 节） | `|ε|>500分`→该候选只出总价，不做拆解 |
| S7 | 输出 | — | 必带门店、抓取时间、口径 |

## 4. 候选生成规则

1. **只换一轮**，其余轮次锁定为默认项（`isDefault=1`；有歧义取 `diffPrice=+¥0` 首项并注明）。
2. **deny 优先于 allow**：如"想喝咖啡"必须剔除 `咖啡味/咖啡风味` 冰淇淋、圣代、麦旋风。
3. 轮域由 `round.name` 与选项名判定（drink / side / main / unknown），`unknown` 不进候选但要在输出里说明。
4. 候选数每次 ≤4 个进入核价，按菜单补差升序取"预算内优先 + 最接近的超预算项补位"。
5. 明确无法可靠映射的意图（控糖无营养数据、减脂、过敏原、清真、素食、人群、上新标签）→ **降级为多选让用户挑或直接拒绝**，禁止用"相近"塞答案。

## 5. 金额与归因口径（不得自创）

```
P  = calculate-price.price                实付总价
PR = calculate-price.productPrice         商品价（券后）
OR = calculate-price.productOriginalPrice 商品原价
A  = OR − PR                              优惠吸收（券 + 套餐自身优惠）
G  = P − PR                               其它费用
d  = choices[].diffPrice                  菜单公示补差

一级：ΔP = ΔM_obs − ΔA + ΔG               （残差恒为 0）
二级：ΔM_menu = Σ 发生替换轮的 d 之差
      ε = ΔP − (ΔM_menu − ΔA + ΔG)
```

- **唯一真值是 `P`**。`d` 只用于解释与排序，**永远不能用来报价**。
- 符号只出现在方向词上：写「券多抵 ¥9.10」，不写「−¥9.10」；净额为负写「还便宜了 ¥1.10」，禁止写「多花 −¥1.10」。
- `|ε| ≤ 2 分`不显示；`3–500 分`标注「未归因差额，以门店结算为准」；`>500 分`该候选只出总价。**永不把 ε 摊进券或其它费用。**

## 6. 硬约束条款

1. 禁止自行推算加价：加价必须来自 `diffPrice`，实付必须来自 `calculate-price`。
2. 券必须来自 `query-store-coupons`；`query-my-coupons` 不校验门店可用性，禁止用于计价。
3. 券参数是**商品级** `items[].couponId/couponCode`，不存在订单级券字段。
4. **套餐内替换不能用券**：服务端会返回 `600012 促销规则不支持该商品`。遇到即如实记录，**不得**假设"有券就会更便宜"。
5. 换掉券绑定商品时必须置顶警示（原券可能失效）。
6. 无候选必须明说"没有"；允许附超预算项但必须显式标注超预算。
7. 任何来自 `diffPrice` 的数字必须带「菜单补差」前缀或 `†`；任何来自 `calculate-price` 的数字标「实付」。
8. 金额内部一律用整数分，展示两位小数。
9. 输出必带：门店码 + 抓取时间（含时区）+ 渠道 + 是否含券。
10. 失败要说失败：接口报错、限流、字段缺失 → 输出原因与已完成部分，禁止静默降级为猜测。
11. 无过敏原数据即无结论；涉及健康问题一律拒绝给判断。
12. `round` 字段官方零文档：若同一候选带 `roundList` 与不带的价格相同，判定核价通道失效，自动降级为「仅菜单补差」并明示。

## 7. 输出模板

```
【改了什么】饮料 可乐中杯 → 大杯鲜萃咖啡（第 3 轮）
【真实多花】多花 ¥1.50        ← 唯一来自 calculate-price
  ├ 菜单补差  +¥1.50
  └ 券        两侧同为无券
【得到什么】大杯咖啡，替换后实付 ¥38.00
【数据】门店 1450713 · 抓取 2026-10-25 15:56 +08:00 · 到店自取 · 未含券
```

预算内无解时：

```
按你的预算和目标，这家店这个套餐里没有符合条件的替换项。
最接近的（均超出预算）：麦咖啡™冰美式中杯 +¥9.00（超 ¥4.00）
```

## 8. 调用预算与限流

- 单次决策典型 8–12 次调用：detail ×1、基线 ×1、探针 ×1、券 ×1、候选 ×4、带券对照 ×1。
- 客户端 ≥200ms 间隔（≤5 rps），429/5xx 指数退避 1s/2s/4s，单会话硬上限 40 次。

## 9. 已知边界

| 边界 | 说明 |
|---|---|
| 无官方 mock | 服务是账号态远程服务，无 token 无法真实调用；公开演示靠快照回放 |
| 到店无满减规则 | `query-promotions` 仅团餐可用，到店凑单优惠只能实测发现，不能预测 |
| 跨套餐不可比 | `diffPrice` 是相对各自套餐的补差，绝对值不可比 |
| 菜单随时段变化 | 早餐时段结构不同，须以抓取时间为准并在输出中标注 |
| `round` 无文档 | 属逆向验证用法，需保留失效检测与降级开关 |
